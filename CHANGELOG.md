# Changelog

All changes compared to the original Castle Story game. Every entry has one tag:
`[ADD]` new feature, `[CHANGE]` changed behaviour, `[FIX]` bug fix, `[REMOVE]` removed feature.

## Unreleased

- [ADD] **AutoRepair / AutoCleanup:** the home crystal's task popup has a button for each range (in blocks) with "+" and "-" over it (Shift: 5 at a time, 5 to 60), and while the crystal's task is selected a ring on the ground around the crystal shows the repair range (green) and the cleanup range (blue), following changes at once. Host only; the value is still the config's `[AutoRepair] Radius` / `[AutoCleanup] Radius`.

- [ADD] **LuaHeapShrink:** shorter garbage collection pauses. The game's Lua keeps captured values in one static array of 10,485,760 slots (240 MB of references plus 40 MB of counts) that every collection reads through; it now starts at 1,048,576 slots and doubles only when they run out.

- [ADD] **MixedRacks:** a weapon stand takes the weapons and armour of all soldier classes at once; before, the first item put on it locked it to that class (a sword made it a knight stand that refused bows, quivers and caps). It still holds as many weapons, props and hats as before, any classes mixed, and equipping takes one whole kit of a single class: the one a call to arms asks for, otherwise the class with the most kits on the stand.

- [ADD] **DevTools:** heap scan (`POST /api/heap/scan`, `GET /api/heap`, MCP `game_heap_scan`/`game_heap`): walks every object reachable from static fields and Unity components, time-sliced, and reports the MB per type and per root and the biggest single objects, to find what fills the managed heap.

- [CHANGE] **GiantBricktron:** giant bricktrons are drawn 1.25x as big (was 1.5x), and a pooled bricktron reused while still scaled is no longer scaled again on top.

- [ADD] **ResourceList:** a "Resources" button on the right-hand bar, under the settings, shows and hides the resource list; the choice is kept in the config (`[ResourceList] Shown`).

- [FIX] **DeconstructColour:** blueprints marked for deconstruction stay dark orange; before, they turned pale white whenever their build task was not selected (after loading or clicking elsewhere), because the game whitens all of a task's blueprint materials while the task is unselected.

- [CHANGE] **CsMenus:** huge performance gains by transferring the in-game UI from Lua UI to C# UI.

- [FIX] **CsMenus:** the selected task, button or saved blueprint gets a thin yellow frame; before, the frame (Unity's Outline) showed through the see-through background as an orange fill.

- [CHANGE] **CsMenus:** the crystal's energy bar in the task popup is blue.

- [FIX] **CsMenus:** with both `CsBuildMenus` and `CsBlueprintLibrary` on, loading a world failed with "unexpected symbol near 'coroutine'": every socket of the left content chain was cut, leaving its first line alone as a statement.

- [FIX] **GlobalBuildJob:** merging a build task into the team's one build task moved only its blueprints; its workers went to the idle group when the emptied task was deleted, so after selecting or making a new build task (as after loading a save) nothing was built and moved buildings were never demolished. The workers now move along with the blueprints, and the build button (and its hotkey) selects the team's build task when there is one instead of making a new, empty one (which also logged a burst of "referenced script is missing" warnings from the game's own build task prefab).

- [ADD] **Performance:** the performance window (F7) and `/api/frames` also show memory: the managed heap's used and reserved size, how much each frame allocates (KB per frame, MB per second), the heap before and after the last garbage collection and how long a frame with a collection takes, and what allocates the most per frame (each measured system's share; [Performance] MeasureAllocations). More is measured on its own: Lua called from C# and Lua coroutines, the workers' task search (finding projects, items, storage, goals), pathfinding and saving; with [Performance] MeasureModPatches (or `/api/frames?mod=true`) every gameplay patch of the mod too. A call that calls itself again (Lua calling C# calling Lua) counts once.
- [ADD] **Performance:** Lua that C# calls is also measured per function ("lua fn Name file:line"), so a spike names the Lua function that took its time, not only "lua: called from C#". uGUI's layout and graphic rebuilds are measured too ("ui: PerformUpdate").
- [FIX] **Performance:** less garbage from the workers' task search: the work limit check, the market's helpers and deliveries and the idle workers' cleanup search no longer make new lists, lambdas or copies of the market's needs every time a worker looks for work.
- [ADD] **DevTools:** the worker trace can be switched on and off from the developer API and MCP (`GET`/`POST /api/workertrace`, tools `game_workertrace` and `game_workertrace_set`). It stays off by default ([Debug] WorkerTrace = false), as it costs frame time while on.

- [FIX] **Performance:** lag spikes of 50-140 ms every second or so. Several features looked up every worker, storage or tool bag with Unity's `FindObjectsOfType`, which walks the whole scene and takes 50 ms or more in a built-up world: the worker limit (twice a second, inside the workers' own update), the worker trace (every second), Stacking (every 3 s), pausing tasks, artificer healing, upgrades, market prices, the giant's home nest, the system log and the debug menu. They now ask a list of live instances kept as objects are made and destroyed (`Core/LiveObjects.cs`). The worker trace also no longer builds a text line for every worker every frame; it compares the parts of the state and only writes the line when one changed.
- [CHANGE] **AutoCleanup:** an item on the roof of a building is taken from the ground beside the building: a worker now reaches up to 12 blocks up (was 4) from a place up to 2 columns out (was 1). A place to stand the worker could not get to (a roof next to the item) is skipped next time and another one tried, instead of leaving the item for two minutes.

- [ADD] **Performance:** F7 opens a performance window ([Debug] PerformanceKey): frame rate now, average and 1% low, frame times (average, p95, p99, slowest) of the last 10 s, garbage collections per minute, a graph of the last 300 frame times (lines at 16.7, 33.3 and 100 ms, slow frames yellow, spikes red, garbage collections marked) and of the frame rate, what takes the time per frame (every Update, LateUpdate and FixedUpdate of the game and the mod, and the game's own update loop per component type, measured from the first time the window opens or with `[Performance] MeasureAtStart`) and the last spikes. A frame over 100 ms (`[Performance] SpikeMs`) is logged with its garbage collections and the five systems that took the most time. Unity's "referenced script is missing" warnings are counted, and the first ones are logged with the C# call that caused them. The developer API has the same numbers at `/api/frames` (MCP tool `game_frames`).
- [ADD] **CsMenus:** `[LuaUi] CsScoreboard` draws the gamemode's top-right panel in C# for invasion, the tutorial and sandbox, instead of the game's Lua panel (InvasionMenu.lua / SandboxMenu.lua, several seconds of a map load): the game's name and time played, the team's players (multiplayer), the minimap, the "build more stockpiles" alert, and for invasion the waves survived, kills by kind, the waves still on the island (enemies left of each kind) and the next-wave timer with its button (host only; the tutorial's "send corruptrons" button). It follows the game's sidebar spacer and is hidden with the scoreboard while a left sidebar is open. Values are read from the gamemode's own Lua a few times a second. Conquest, credit island and grab the gems keep the game's Lua panel. Off by default.
- [ADD] **CsMenus:** groundwork for drawing the game's in-game menus in C# instead of its Lua menus, which take most of a map's loading time to build (GameMenu about 25 s, the gamemode panel about 11 s). The game's menu logic (menu groups and handles: labels, icons, actions, hotkeys) stays in Lua; only the views are to be replaced, one part at a time, each behind its own `[LuaUi]` switch (CsScoreboard, CsBars, CsBuildMenus, CsSettings, CsTooltips, CsTaskPopup, CsTaskList, CsBlueprintLibrary; all off, and a part that is off changes nothing). This release has the kit only: a shared canvas that scales and sorts with the game's menus, widgets in the game's look (icon buttons with hover label, count and hotkey, sections, grids, progress bars, counters, scroll lists, tooltips), C# views that draw the game's Lua menu handles and groups and call their actions, and the hand-over of GameMenu's tables to C#. `[LuaUi] CsSmokeTest` shows a C# copy of the right bar to check it in a game.
- [ADD] **CsMenus:** three more parts of the in-game menu can be drawn in C# (each off by default, restart to apply): `[LuaUi] CsBars` the top bar (selected task's name), the left bar (score, blueprints, new task, structures, blocks, task count) and the right bar (home, settings, help, back to work, call to arms and the mod's buttons); `[LuaUi] CsBuildMenus` the new-task sidebar and the building and block catalogues; `[LuaUi] CsSettings` the settings sidebar and the "Paused" notice. The game's Lua views of these are no longer built while a map loads: the bars' menus and the sidebars' load events get a recorder that notes what the game and mods add to them (in order), and the C# views draw from that, using the game's own buttons' logic, groups and hotkeys. The blueprint library sidebar stays the game's.
- [ADD] **CsMenus:** `[LuaUi] CsBlueprintLibrary` draws the blueprint library (the name field with its save button, load, publish to the Workshop, delete and the saved blueprints with their thumbnails) in C# beside the left bar; its Lua sidebar is no longer made. The game's key bindings are off while a name is typed, as in the game's own field. Off by default; restart to apply.
- [ADD] **CsMenus:** `[LuaUi] CsTooltips` draws the in-game tooltips and the help in C#. No article menu is built while a map loads any more (53 tooltips twice and 22 help pages): the two tooltip menus are replaced by stand-ins with the same events, so the task popup, the task list and the crew buttons show a C# tooltip (above the hovered button) drawn from the article's items when it is needed, and the help sidebar is drawn in C# while it is open, with its links and the tutorial's next buttons. The mod's quarry and loop limit lines in those tooltips show as before. `[LuaUi] LazyArticles` does nothing while this is on.
- [ADD] **CsMenus:** `[LuaUi] CsTaskPopup` draws the selected task's popup over the task list in C# (off by default, restart to apply): build and blueprint options, landscape, quarry, tunnel and harvest options, goals, priority, ok / apply / cancel / delete, the workshop's recipes, input, output and queue, and the crystal's population, energy bar and spawn button, with the mod's own buttons in it (work limit, pause, build needs, quarry resources, depth and limits, loop limit, workshop priority) and their small + and - over the top. Menu_Popup.lua is no longer built; GameMenu's popup field gets a recorder with the popup's events, its sections are filled by their own ev_onLoad listeners, and every button acts through its handle, so hotkeys (the recipe slots) and multiplayer commands work as before. It stands over the selected task's row of the game's or the C# task list. Tooltips are the C# articles with CsTooltips, else the button's name. The C# task tooltips also follow the C# task list's rows.
- [ADD] **CsMenus:** `[LuaUi] CsTaskList` draws the task list along the bottom of the screen (each task's icon, name, priority and crew faces, the idle group, the melee and ranged units) in C#, instead of the game building a pool of 20 or more task panels with their crew panels when a map loads. A small Lua table takes the place of the Lua menu and keeps its task slots, hooks and actions, so clicking works as before: a task selects or deselects it, its crew selects the crew, right click assigns the selected bricktrons (or, on the idle group, unassigns them), Shift and Ctrl raise and lower the priority; the task popup and the task tooltip, still the game's Lua menus, are pointed at the C# rows. Off by default; restart to apply.
- [CHANGE] **CsMenus:** the C# menus' buttons lighten under the mouse, the build catalogues' icons fill their cell, and the panels' background is slightly see-through (alpha 0.85).
- [FIX] **MoveStructure:** the click that picked a building to move also placed its blueprint: a new blueprint landed next to the building instead of it being moved (when the build project had to be selected first, the building was put in the hand a frame later and the same click placed it as a normal blueprint). Placement now waits until that click is released, and the next click moves the building. Picking a building to move also no longer selects the build task or opens the blocks or structures catalogue: the move goes into the team's build task. A move ordered while the repair task was the last build task selected went into the repair task, which nobody works on, so the old building was never demolished and nothing happened; moves now always go into the team's build task with the most workers (GlobalBuildJob; after loading a save picking a building no longer makes a new, empty build task for it) and are committed at once. The log says where each move went, or why it was refused.

- [FIX] **Pathfinding:** lag spikes when many bricktrons or enemies searched for a route at the same time. Every running search took its slice (100 nodes, 50 for an enemy) each update on the main thread with no limit per frame, so a frame could take as long as all of them together (up to 0.9 s was measured). Route searches now share a time budget per frame (`SearchFrameBudgetMs`, 6 ms); the others carry on in the next frame, and a search held back three frames in a row runs regardless. The searches stay on the main thread: they ask the game's objects whether a voxel is blocked and whether the target is reached, and read the navigation graph that changes with the terrain. A single search slice over 100 ms is logged with the garbage collections during it.
- [CHANGE] **MixedStockpiles:** bricks, wood logs and planks are no longer mixed with other resources on a stockpile: they were added to `[MixedStockpiles] NeverMix`, so each gets a pallet of its own. An existing config keeps its own list; add `StoneBlock,WoodBlock,PlankBlock` to it there.

- [CHANGE] **FasterLoading:** new `LuaUi` setting `LazyArticles` (off by default for now): the game UI opens a menu for every tooltip article (twice) and every help article while a map loads; with it on, an article's panels are made the first time it is shown (a tooltip when first hovered, a help article when first selected or when the help opens on it) and then kept as before. The load timing log now also ranks each step of a Lua menu's build (where it yielded: file, line, function), and timing every C# call from Lua costs less while loading (no text or table work per call).
- [ADD] **CriticalHits:** bricktrons from combat level 3 land critical hits for double damage: a 5% chance per sword strike or shot at level 3, 10% at level 5, 15% at level 8 and 20% at level 10. A red "2x damage" rises over the bricktron that made it (when the strike lands, or when the shot leaves), and its weapon glows red for that hit: the sword through its swing (its metal recoloured red over its upgrade tier, with a red light), the arrow, bolt or magic shot and its trail in flight (their picture recoloured, as the game's shaders have no colour to tint). Healing bolts never crit. The host rolls the hit and doubles its damage; the looks are sent to multiplayer clients (who need the mod). The heal bolt's green tint is now a shared tint (`GlowTint`) used for both, and recolours the bolt's picture too.
- [FIX] **Upgrades:** researched tiers did not show on the bricktrons' gear: only the material's colour property was tinted, which the game's gear shaders do not use (and tier 1 was too faint to see anyway). The metal of the gear's picture (its grey, unsaturated pixels) is now recoloured instead, so wood, leather and team colours stay: iron dark bluish grey, steel bright silver, crystal blue with a glow. All equipped gear of the team changes the moment a tier is researched. The log names each gear material's shader and properties once.
- [CHANGE] **BlueCrystalDeposits:** fewer blue crystal veins in the deep rock: the vein noise threshold went from 0.6 to 0.65 (the share each noise takes is logged when a map loads). Deep rock not yet dug out on existing maps gets fewer veins too, as it is generated again from the map's seed on every load.
- [FIX] **BlueprintRenderer:** a blueprint whose block's mesh descriptor has a block outside the blueprint's own cells made the game throw `KeyNotFoundException` in `BlueprintRenderer.RebuildMesh` (seen once after loading a save). The blueprint now keeps its plain ghost mesh, and the log names the blueprint, its cells and the missing block. The cause, for the 1 x 4 and 2 x 4 stone bricks: a new blueprint whose middle falls between two cells (a 4 long brick at the world's origin, before it is put in place) had its ghost blocks rounded one by one, to the even number, so its last block landed past its last cell, and its ghost could stay without its block-by-block mesh once placed. Ghost blocks are now rounded as the blueprint's cells are (the root cell once, whole blocks from it); placed blueprints are unchanged.
- [CHANGE] **Upgrades:** with Stacking researched, stockpiles stack their layered goods (bricks, logs, planks, ingots, glass, terracotta, brimstone, barrels, ropes, fabric, crystal chunks) higher than the pallet's own 2 layers: Stacking gives 33%, 67% and 100% more room (up to 4 layers at the third tier), and the layers above the pallet's own two are drawn with the pallet's own pieces, filled one by one. Goods kept in the crate (stone, raw iron, crystals, plant fibre...) get the same 33%, 67%, 100%; the crate is as much taller and its heap rises as much higher. Large stockpiles get the extra layers and taller crates too. Looks are drawn on every machine from the team's tier and the stockpile's content.
- [FIX] **AutoCleanup:** idle workers kept failing to pick up gear and items lying against a wall (each try "PathExecutionFailed" after 3 s, again every two minutes). An item pushed partly into a wall or block has its place inside that block, where no worker can stand, and the foot search only looked below the item. Such an item is now picked up from a place beside it, level with it or lower.
- [ADD] **Upgrades:** the research station's window shows how many dark crystals (blue crystals without DarkCrystals) the stockpiles hold, in its header next to the title, kept up to date while it is open.
- [CHANGE] **DebugMenu:** the invasion waves row also has +10 min and +15 min before the next wave, and the enemies row a "100% critrate" switch: every hit and shot of the player's bricktrons is a critical hit, whatever their level (not saved).
- [FIX] **Experience / Upgrades:** the ranged damage bonus of a bricktron's combat level (+5% per level) and of Fletching did nothing for shots: the game hands the shooter's ranged damage to the bow, but an arrow, bolt, magic shot or thrown rock always did the fixed damage of its kind. A shot now keeps its shooter's bonus when it leaves (and a critical hit's double) and its hit does that much more; the shared attack of its kind is left unchanged.
- [FIX] **StockpileConsolidation:** many idle workers kept carrying the same stone between stockpiles. A mixed stockpile whose columns were all taken still counted as having room for its resource, so it was picked as the target, the load could not go in, and the worker stored it in the nearest stockpile, which became the next one to empty. The target's real room for the item is now checked, and a stockpile that was just given a load is not emptied again for five minutes. A move is only made when it empties the source of that resource in one trip (all of it fits in the worker's hands and in the target); with more room per stockpile (Stacking) workers otherwise moved one stone at a time between half-full stockpiles without end.
- [CHANGE] **SaveAndLeave:** the quit dialog's "SAVE & LEAVE" is now "SAVE AND RETURN TO MAIN MENU", and a new "SAVE AND QUIT GAME" saves and closes Castle Story after a confirmation dialog. Extra dialog buttons added for the longer quit dialog are hidden again in shorter dialogs (the confirmation showed a second CANCEL).
- [ADD] **WorkLimit:** how many bricktrons work on a task at a time can be set, for example a quarry with only 4: a "Workers at a time" button among the task's actions shows the limit ("All" for none) with small "+" and "-" over it. Once that many work on the task (its crew, helpers from other tasks and free workers alike) no one else takes work from it, and any more than that stop, those outside its crew first. Its crew is kept to the limit as well (a larger crew is cut down to it, the rest go to the free workers, and no more are hired), and the task's marker shows the limit in place of the crew size ("x 0/4" rather than "x 0/8"). Synced to multiplayer clients and saved with the task.
- [ADD] **Upgrades:** a progress bar over the head of the worker researching at the research station shows how far the current tier is (yellow on dark, the same size at any distance); it shows while the worker works on the research and goes when it stops or the tier is done. Host only: the research time is counted by the host.
- [ADD] **WorkshopPriority:** a workshop's priority (research station, smithy, armoury, market, furnace...) can be set like a task's: "-" and "+" in its queue menu step it through locked, low, medium and high. The game kept every workshop at high and ignored changes. Saved with the workshop and synced to multiplayer clients.
- [ADD] **BuildPriority:** a single blueprint, for example a warehouse being built, can get top priority from the context wheel over it (a star button, "Top priority"; the same button again gives "Normal priority"). Builders look at prioritized blueprints first and take one whenever they can fetch for it or build it, however far away; a yellow ring marks it. Saved with the blueprint; a multiplayer client sends the change to the host.
- [CHANGE] **Market:** a trade is never "too expensive" any more. A trade gives a fixed lot and asks as much as that lot costs at the current prices: when prices rise, more is given for the same lot (the amount follows the prices until the trade is made, also for the order being worked on). When the lot would cost more than the market holds of a resource (120), the lot gets smaller, down to one; one is always given. Before, a trade asked a fixed amount and gave nothing (the goods back) when the prices were too high.
- [CHANGE] **ResourceList:** a resource stays in the list from the first time it is stocked, for good: also at 0 and after the world is saved and loaded again (it was forgotten when the game was left). Remembered per team and saved on the team (`seenResources`). **Storage free** also shows the free room as a percentage of the total.
- [ADD] **PauseTasks:** a task can be paused instead of deleted. A pause button among the task's actions (next to delete) stops all work on it: no bricktron takes work from it, and those working on it stop at once; pressing it again resumes the task. The task keeps its blueprints, zones and settings. Its crew are released to the free workers while it is paused, so it shows no one assigned, and are put back on it when it is resumed (those not given another task meanwhile). Synced to multiplayer clients and saved with the task (a spare bit of the game's task state).
- [CHANGE] **CustomBlocks:** a long stone brick is drawn as one whole stone instead of the game's 1 x 2 brick laid end to end (a 1 x 4 looked like two bricks, a 1 x 3 like a brick and a half); a 2 x 2 or 2 x 4 is one wide stone too. It is the game's 1 x 2 brick (a plain box) pulled out to the brick's width and length, with its own texture: every face shows the game's picture of it at the same size per block, its joints and bevels as they are and its middle continued, so nothing is stretched and both ends look the same. The texture is made while the game runs from the game's own brick texture. The brick wheel icons of the stone bricks look like the game's own brick icons: flat grey faces, a thick outline and the same view.
- [CHANGE] **Market:** coal and steel are traded too (with Metallurgy): coal for and to every other good, steel only given away (no trade gives steel). Their trades are made after every other recipe, so saved queues keep their trades.
- [ADD] **Market:** several workers fetch for the same trade. Next to the market's own worker, up to `[Market] MaxHelpers` (6, up to 20) others bring what the current trade still needs; every fetch says what it brings and the rest leave that out, so a big lot is split over the workers instead of each bringing all of it. Each brings an even share of the lot (at least 5, at most one trip of 20), so a small lot is fetched by several at once too.
- [FIX] The recipes made after the game has set up its own (metallurgy, research station, market coal and steel trades) are made in a fixed order, so their ids stay the same between runs and saved queues keep their recipes.
- [FIX] Recipe ids above 255: a workshop's queue kept 8 bits per order, so recipes made after the 255th (the coal and steel trades) could not be queued. The high byte of each order is now kept beside the game's queue, synced and saved (`recipesHigh`); old saves load as before.
- [CHANGE] **GiantBricktron:** with the Upgrades feature, giant bricktrons can only be made once Giant Bricktrons is researched at the research station.
- [ADD] **Upgrades:** a research station in the build menu (crafting group, 10 planks, 6 bricks, 2 glass): an open laboratory, 4 x 3 blocks, with bookshelves, an alchemy table, a reading desk with a glowing dark crystal and piles of books. Workers research colony upgrades there in three tiers (Novice, Adept, Master), paid in dark crystals (blue crystal without the DarkCrystals feature), for the whole team and kept in the save. A tier takes one worker 5 minutes of work, counted in time rather than hammer strokes; a worker called away leaves the research where it is and the next one carries on (also after loading a save):
  - **Housing:** +5, +10, +15 bricktrons over the limit of 15 (30, 60, 120 crystals).
  - **Work Methods:** +10%, +20%, +30% work speed (20, 40, 80 crystals; so are the others).
  - **Stacking:** stockpiles and warehouses hold 33%, 67%, 100% more; stockpiles stack layered goods higher (up to 4 layers instead of 2) and their crates are taller.
  - **Crystal Attunement:** a new bricktron costs 15%, 30%, 45% less energy.
  - **Light Boots:** +5%, +10%, +15% walking and running speed.
  - **Firefly Lore:** each brewed firefly carries 10%, 20%, 30% more energy.
  - **Giant Bricktrons:** one tier (60 crystals) that has to be researched before a giant bricktron can be made.
  - **Scouting:** 15%, 30%, 50% more time between invasion waves. The wave timer is shared by everyone, so the best tier any team has counts; the first wave keeps its time.
  - **Efficient Mining:** every stone, ore or crystal that comes out of the ground has a 10%, 20%, 30% chance of coming with one more of the same kind: terrain a worker digs out (dig and quarry zones, levelling, blue crystal veins) and the natural rocks, iron and brimstone deposits workers mine. Plants, trees and broken-down built blocks keep their yield. Its research recipes are made after every other recipe (the market's coal and steel trades too), so saved queues keep their ids.
  The research recipes are made after the metallurgy recipes, so the ids of the recipes before them stay as they were.
- [CHANGE] **AutoCleanup:** an item lying on top of a building or a stockpile, where no worker can walk, was left there for good. The worker now takes it from the foot of it: from a place it can stand on right beside the item and 1 to 4 blocks lower. When that fails too, the item is left alone for 2 minutes.

- [FIX] **LargeStockpile:** a large stockpile of coal, steel or dark crystal looked empty: the pallet has no display for the mod's resources. They are now drawn as their own model stacked in each block of the stockpile.

- [ADD] **AutoRepair:** idle builders repair damaged blocks near the base (within `[AutoRepair] Radius`, 15 blocks, of the home crystal or a stockpile) without a repair zone, as the repair order does: no materials. Real work comes first and interrupts it. Blocks hit in the last 20 seconds, blocks inside a repair zone and blocks a worker could not get to in the last minute are left alone. The game picked a wave's spawn point at random only when the wave spawned; the host now picks the next one ahead and sends it to every player with the wave timer (kept in the save). From 30 seconds before the wave (`[WaveDirection] ShowSeconds`) a red arrow on the edge of the screen points at the spawn point, or over it when it is on screen, and it stays 15 seconds after the wave arrives (`HoldSeconds`).
